多邻国课程与内容百科

1. 课程不是一个列表，而是一套内容编排系统

多邻国的课程需要从三个层面阅读。第一层是**学习对象**：语言、数学、音乐、象棋等；第二层是**课程路径**：Section、Unit、Level、Lesson；第三层是**练习材料**：词汇、语法、发音、听力、阅读、翻译、对话和情境任务。用户在 App 中看到的是一条可继续的路径，但后台需要同时管理目标、依赖、题目版本、难度、复习和进度。

官方公开资料对语言课程的描述是：每个 Unit 围绕一个沟通目标，覆盖实现该目标所需要的词汇和语法；练习逐步从识别走向更主动的输入。课程内容不是简单的“单词表”，而是由主题、功能和题型组成的学习序列。

2. 课程目录的工作分类

| 课程族 | 内容对象 | 主要目标 | 研究时的注意事项 | |---|---|---|---| | 语言课程 | 词汇、语法、听说读写、对话、故事 | 沟通目标与熟练度 | 语言方向不同，内容和路径可能不同 | | 数学课程 | 数字、运算、模式、问题解决 | 数学基础和应用 | 题型与语言课程不同，不能直接套用词汇模型 | | 音乐课程 | 音高、节奏、读谱、键盘交互 | 音乐基础技能 | 设备输入和声音反馈成为关键条件 | | 象棋或策略内容 | 规则、局面、选择、复盘 | 规则理解与决策 | 产品状态和课程是否长期开放需实测 | | 故事/情境内容 | 对话、阅读、角色、场景 | 理解和应用 | 可能只对部分语言方向开放 | | 复习内容 | 已学材料、错题、薄弱技能 | 保持和重新提取 | 推荐逻辑可能随版本变化 |

“课程族”是研究分类，不代表每个用户都能看到全部内容。任何课程目录必须附上观察日期、地区、平台、语言方向和账号状态。

3. 课程树的字段

Course
  id / title / source_language / target_language / subject
  Section
    id / title / communication_goal / score / cefr_or_standard
    Unit
      id / title / topics / vocabulary / grammar / estimated_time
      Level
        id / type / difficulty / completion_condition
        Lesson
          id / objective / exercise_sequence / xp_reward
          Exercise
            id / type / prompt / answer / hint / skill / version

这棵树把内容结构和界面结构连接起来。用户点击的是卡片或节点，系统实际读取的是课程对象、状态和下一节点规则。一个 Unit 的标题、颜色和插画属于展示层；沟通目标、题目依赖和复习间隔属于内容层；完成状态、奖励和推荐属于进度层。

4. Section：章节层

Section 是课程中的较长章节。它把多个 Unit 放在一个更大的沟通或能力范围里，并给用户一个远期方向。Section 页面通常承担三种任务：显示当前所在位置、允许回到已完成章节、展示后续章节和能力范围。部分官方资料还把 CEFR 等外部标准和 Section Score 连接起来。

研究 Section 时至少记录：章节名称、颜色、Unit 数量、当前进度、Score 的含义、是否显示能力说明、已完成和未来章节是否可点击。要把“章节完成”与“能力达成”分开：前者是产品状态，后者需要独立的能力测量。

5. Unit：内容目标层

Unit 是课程编排的主要工作单元。一个 Unit 应回答“学完后能做什么”，而不是只回答“会哪些词”。它可以围绕旅行、家庭、工作、饮食、时间、位置、请求、叙述等情境组织词汇和语法。Unit 内的题型顺序往往从识别、理解、选择逐渐走向输入和生成。

Unit 的设计记录应包含：

  • 沟通目标；
  • 词汇集合及出现顺序；
  • 语法或结构主题；
  • 听说读写的分布；
  • 题型和难度如何递进；
  • 复习如何插入；
  • 练习是否使用同一情境材料；
  • 完成后用户看到什么反馈。

6. Level 和重复练习

Level 可以理解为 Unit 内的重复和进阶层。它不一定表示新的知识点，也可能表示对同一主题进行更多练习、不同题型或更高要求。若出现 Legendary 或类似的高阶状态，研究者需要确认它是额外挑战、复习还是课程必经路径。

重复练习的价值取决于它改变了什么。如果只是把同一道题再做一次，用户可能获得界面熟练；如果改变了材料、延迟、干扰和生成要求，才可能检验更广泛的掌握。产品研究应把“重复”拆成内容重复、技能重复、题型重复和操作重复。

7. Lesson 与 Exercise 的内容协议

一节 Lesson 不是一张卡片，而是一个有开始、进行中、提交、反馈、结束和退出的会话。每个 Exercise 都需要一个目标能力、输入方式、正确答案、可接受变体、提示、错误反馈和下一题规则。

常见的练习分析维度包括：

1. **识别**：从选项中理解词、句或声音； 2. **匹配**：把文字、图像、声音或含义配对； 3. **回忆**：在没有完整提示时想起内容； 4. **输入**：键入、选择字母、拼写或组织句子； 5. **听辨**：从声音中识别词、句或语法结构； 6. **朗读/口语**：使用麦克风或语音识别完成输出； 7. **理解**：阅读或听完情境后选择含义； 8. **生成**：在开放程度更高的条件下表达内容。

这些是题型功能，不是疗效分类。题型能调用某种过程，不代表长期训练一定提高该过程。

8. 每日任务如何连接课程树

每日任务通常不直接说“请完成 Section 2 的 Unit 4”，而是以用户可理解的行为目标表达：完成一节 Lesson、获得若干 XP、进行复习、完成朋友任务或达到某种练习条件。后台事件再把这些行为映射到课程和任务系统。

Lesson 完成
├── Course：Level / Unit 进度更新
├── Exercise：错题、提示和速度写入学习记录
├── Daily Goal：当天目标增加
├── Streak：当天连续日满足
├── XP：经验值增加
├── Monthly Quest：Quest Points 增加
├── Friends Quest：共享目标增加
├── League：周排名可能变化
└── Profile：个人记录、徽章或 Feed 可能更新

这个连接是多邻国产品设计的关键。用户只做了一节课，但系统让同一个行为在多个时间尺度上产生回声。研究者应逐项记录哪些状态真的更新、哪些只是界面动画，不要假设所有奖励都会在每个版本同时出现。

9. 复习、回看和课程外学习

用户并不只能沿着当前路径向前。官方资料介绍过从 Section 菜单回看已完成内容，也允许对旧材料进行复习。课程外内容还可能包括故事、角色任务、专项练习、活动和社交任务。它们的共同点是：重新调用已学材料，但提供不同入口、情境或奖励。

复习入口需要区分：

  • 用户主动选择某一 Unit；
  • 系统根据错误或间隔推荐；
  • 快速复习用于保持 Streak；
  • 活动任务要求某种题型；
  • 订阅或商店提供额外练习。

这些入口的学习内容可能重叠，但用户意图不同。产品研究不能只看内容是否相同，还要看入口文案、预期时间、反馈和奖励是否改变。

11. 反推 BrainLab 的课程设计

多邻国值得参考的不是“把脑部训练做成语言课程”，而是它把内容目标、可完成任务、即时反馈和长期路径连接起来。BrainLab 若设计认知训练课程，也需要先定义每个 Unit 的可观察能力目标，再决定题型、提示、难度和复习，而不是先做一个有颜色的关卡地图。

一个合格的 BrainLab Unit 应明确：训练哪一种可操作过程、用户要完成什么任务、任务内部成绩如何记录、独立任务如何测量、什么时候复习、怎样恢复中断，以及哪些结果不能被解释成疾病预防。这样才能借鉴课程结构，同时保留医学和研究边界。
