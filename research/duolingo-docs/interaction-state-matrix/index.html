多邻国交互状态矩阵

使用方法

这张矩阵用于逐屏复盘多邻国。每次观察先写版本、平台、账号、课程和日期，再按“进入前—进行中—完成—失败—恢复—退出”记录。表中的“已知”表示官方资料或稳定界面直接支持；“待测”表示需要当前版本实测。不要把一个历史截图扩展为所有用户的固定流程。

个人档案状态

Profile 不是一个静态名片。它至少有四个状态：未完成身份、基础档案、公开档案和隐私限制档案。用户可能在不同时间拥有不同 Avatar、语言、Streak、League 历史和成就集合。研究时要拍摄“刚完成徽章后”“刚达到个人记录后”“关闭公开档案后”三个时刻，观察内容是否即时更新。

成就可以按触发逻辑分为：首次行为、数量里程碑、连续行为、个人纪录、社交行为和特殊惊喜。徽章的视觉差异、名称、稀有度、进度条和是否可分享共同构成奖励语法。不要只记录图标；要记录它如何被发现、如何被领取、是否产生通知、是否改变档案首屏和是否进入 Feed。

商店、订阅和恢复

商店流程应按完整状态记录：进入商店 → 选择商品 → 查看余额/价格 → 确认 → 成功 → 库存或权益更新 → 返回任务。失败状态包括余额不足、网络失败、支付取消、订阅恢复失败和地区不可用。用户必须能理解购买的是一次性道具、订阅权益还是家庭成员名额。

订阅的关键不是宣传页面，而是限制出现的那一刻。研究者需要记录：限制弹窗在什么行为后出现、用户能否继续免费任务、关闭弹窗后回到哪里、是否显示试用结束日期、取消入口是否可见。BrainLab 后续不能复制“疾病焦虑—付费解锁”的结构。

通知、Widget 和 App Icon 的状态

应用外触点有自己的状态机：

无提醒 → 资格满足 → 生成提醒 → 系统展示 → 用户打开/忽略
→ 深链进入目标页 → 完成或关闭 → 频率与偏好更新

动态 App Icon、Widget 和通知可能分别由连胜、活动、朋友互动、每日目标或未读 Feed 触发。记录时要注明系统权限、设备、时区、是否开启通知、点击后的落点和用户完成行为。相同文案在早晨、深夜和连胜即将中断时可能有不同体验含义。
