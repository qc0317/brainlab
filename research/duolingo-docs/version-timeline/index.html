多邻国产品版本与功能演化时间线

读法

这是一条“公开证据时间线”，不是完整的内部发布历史。日期来自官方产品文章或帮助内容的发布日期/更新时间；它证明某个设计在该时间被公开介绍，不保证今天所有用户仍能看到相同界面。每一条都要结合当前平台、地区、课程和账号实测。

2018：排行榜成为周周期竞争

官方回顾称，Leaderboards 在 2018 年开始测试，之后扩展为更多 League 层级。设计重点从个人学习记录延伸到跨课程的周周期比较。可观察到的核心结构是：匹配一组用户、积累 XP、按周结算、晋级或下降。

**产品意义：**把“我今天完成了一课”连接到“我这一周在群组中的位置”。

**研究边界：**官方文章的历史回顾不能证明当前匹配算法、League 数量和晋级区间仍相同。

2019—2020：Streak、Freeze 与习惯实验

官方连胜文章把 Streak 定义为连续完成学习日，并讨论了 Streak Freeze 等保护机制对回访的影响。连胜由一个非常简单的事件驱动：当天是否完成满足条件的学习行为。后续产品把火焰、日历、提醒、冻结和补救组合成一套可见的连续性系统。

**产品意义：**用过去的投入提高今天的行动价值，同时用保护机制降低偶然中断的永久损失。

**研究边界：**历史增长数字是特定实验和时间段的结果，不能直接迁移到 BrainLab 或解释为认知疗效。

2021—2022：Friends Quest 和轻关系协作

官方 Friends Quest 文章介绍了每周与朋友共同完成目标、共享进度、发送预设鼓励和 XP Boost 的流程。它还说明了配对资格、移动端限制和退出开关等细节。

**产品意义：**不要求用户持续聊天，而是让朋友在同一时间做各自的 Lesson，降低社交表达成本。

**研究边界：**好友任务的配对、奖励、平台和地区规则可能已经改变；文章中的截图是历史界面证据。

2022—2023：成就、个人纪录和档案收藏

官方成就设计文章介绍了把成就集中到 Profile，并加入个人纪录，例如最长 Streak、每日最高 XP、完美课程和最高 League。成就从简单的“完成过”扩展为“超过自己的历史最好成绩”。

**产品意义：**把过去行为变成可以回看的身份资产，避免奖励只在完成瞬间消失。

**研究边界：**徽章名称、等级、视觉资产和解锁条件需要当前版本截图核对。

2023—2024：课程目标、Score 与多学科扩展

官方 Duolingo 101 介绍了 Unit 以沟通目标组织内容、练习覆盖听说读写、课程路径逐步增加主动输入，并说明 Score 用于表示课程进展。同期官方对数学、音乐等新内容的发布说明显示，主 App 开始承载不同学科，但课程结构不能假定完全相同。

**产品意义：**产品模型从“语言课程 App”扩展为共享游戏化框架下的多学科学习平台。

**研究边界：**不同学科的内容树、Score 定义、资源限制和题型需要独立观察。

2024—2025：核心标签与跨页面设计系统

官方 Core Tabs Redesign 文章展示了 Quest、League、Profile、Feed 等页面的统一重构。设计团队讨论了标题层级、颜色、间距、卡片、导航和页面家族感，而不是只改一个页面的视觉。

**产品意义：**当功能越来越多时，视觉系统承担“这是同一个产品”的认知整合，并减少用户在不同标签间重新学习界面的成本。

**研究边界：**官方文章中的探索图和最终图是设计过程证据，不等于当前每个平台的最终实现。

2025—2026：活动、视频/对话和更复杂的内容表面

公开产品文章持续展示月度 Quest、角色主题、视频或对话类练习、好友动态和跨学科内容。活动表面越来越多，产品需要通过核心标签、统一标题和任务中心把它们组织起来。

**产品意义：**限时内容成为课程主干之外的回访入口，但也增加了信息架构、通知和资源经济的复杂度。

**研究边界：**活动名称、可用地区、订阅权益和图标变化不能凭文章标题推断，必须在观察卡中标记“当前未实测”。

当前版本研究的时间记录

在没有当前 App 账号实测前，BrainLab 不把下列内容写成确定事实：

  • 当前底部导航是否仍为相同标签；
  • 每日任务和月度任务是否共用 Quest 页面；
  • Energy 是否成为语言课程的统一资源；
  • 动态 App Icon 和世界杯/节日活动是否仍可获得；
  • Profile 的 Avatar、徽章、Feed 和公开设置是否同一版本；
  • Score、XP、League 和课程完成的计算关系；
  • 订阅权益和 Hearts/练习限制的当前价格与规则。

时间线对 BrainLab 的设计启示

多邻国的演化显示，产品不是一次设计完成的功能集合。先有课程和每日完成，再叠加 Streak；再用 League 和 Friends Quest 增加社会关系；再用 Profile 和徽章把行为沉淀为身份；最后用 Quest、联动和多学科内容增加短期入口。每一次叠加都会创造新价值，也会增加导航、通知、隐私、资源和公平问题。

因此 BrainLab 不应一次复制所有层。应先建立训练内容树和单次任务，再选择一个可恢复的连续机制；在有真实用户关系后再考虑小组协作；只有当信息架构能够承载时，才增加活动、头像、徽章和资源经济。时间线本身应成为设计约束：每增加一个系统，就记录它依赖哪些已有状态、增加哪些事件、带来哪些退出路径。
