# 多邻国界面截图观察工作簿

## 目的

截图不是装饰，也不是把品牌界面复制到 BrainLab。每张图应回答一个交互问题，并与产品状态、用户目标和设计推断相连。官方页面截图先作为远程来源登记；如果未来保存本地文件，必须记录访问日期、文件哈希、裁剪范围、许可状态和来源 URL。

## 截图类别与观察问题

| 类别 | 必须观察的元素 | 关键问题 |
|---|---|---|
| 首页/学习 | 主按钮、课程节点、Streak、每日目标 | 用户三秒内知道今天做什么吗？ |
| Section/Unit | 章节、Unit 标签、Score、已完成/未来 | 长期进度和下一步是否同时可见？ |
| Lesson | 题干、输入、提交、提示、题数 | 单题状态是否稳定，错误如何恢复？ |
| 结果页 | XP、Streak、Quest、继续按钮 | 一个 Lesson 的多系统更新是否能被理解？ |
| Monthly Quest | 月份、主题、点数、里程碑 | 限时叙事是否增加目标而不制造焦虑？ |
| Side Quest | 角色、剧情、额外关卡 | 它和主课程的内容、奖励、入口如何关联？ |
| Leaderboard | 周期、排名、晋级区、用户 | 排名表达的是 XP 还是能力？压力是否可控？ |
| Feed | 好友动态、公告、未读、深链接 | 消息是否能直接引导下一步行动？ |
| Profile | Avatar、Streak、徽章、个人纪录 | 档案如何把行为转成身份？ |
| Achievement | 徽章图形、进度、解锁、分享 | 成就是自动发现还是需要领取？ |
| Shop/订阅 | 商品、价格、权益、关闭、取消 | 商业化是否阻断核心学习？ |
| App 外触点 | Widget、通知、动态图标 | 用户能否理解触发原因和返回路径？ |

## 资源保存规则

优先链接官方公开页面，不下载或重新发布完整品牌截图。研究所需的本地副本应只保存必要裁剪，并在文件名中包含来源 ID、日期和版本，例如 `official-core-tabs-redesign_2026-10-12_v1.png`。正文使用文字转述，图片只支持对布局、层级、状态和交互的分析。

## 版本比较

同一类别至少需要两次观察才能讨论变化。比较时按“新增、删除、改名、位置变化、默认状态、反馈变化、入口变化、付费边界变化”记录，不使用“更好看”“更有粘性”等未经测量的结论。
