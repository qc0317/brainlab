每日会话与完整体验流程

Concept → Framework → Detail → Experience 落到一个可测试流程。

design-session · 设计分析 · 待验证 · 更新 2026-10-09

流程草案

阶段用户看到什么系统做什么失败与恢复
适配兴趣、输入/视听支持、时间偏好选择低负担起点跳过非必要配置
准备一条规则、演示、预计时长保存规则/参数版本先试一题
执行固定操作与明确进度记录正确/提示/暂停暂停、提示、结束
复盘具体表现、轻量负荷提问分别保存完成和负荷允许稍后反馈
下次可解释的计划先改一个难度条件中断后恢复
回顾参与与具体任务变化比较相同规则条件注明版本变化与缺失

示例会话 · 非处方

可用“示范 → 一项熟悉任务 → 一项适度挑战 → 复盘”验证流程。任务数、时长、强度与休息间隔还没有证据支持，不能成为默认医疗建议。原型应支持用户提前结束并保留记录。

关键交互验收

  • 无需解释能找到开始、提示、暂停和结束。
  • 错误后能知道哪里出错和可如何继续。
  • 大字号、键盘、触控、减少动效条件下主要路径可用。
  • 完成后能正确说明分数不代表个人 AD 风险。
  • 中断后能恢复，且不因连续天数损失而感到被惩罚。
