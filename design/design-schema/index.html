知识库结构、编辑与 Git 流程

内容数据驱动多级页面、检索和关系，便于以后扩充与迁移。

design-schema · 结构方案 · 已实现 · 更新 2026-10-09

本期能力

内容存储于 GitHub 的 JSON；构建脚本生成首页、专题目录、详情、来源目录和检索索引。没有在线编辑、用户账户或个人健康数据后台。来源、知识条目、游戏需求和关系有稳定标识，可继续扩充。

数据实体

实体主要字段编辑位置
来源id、URL、类型、年份、读取范围、局限data/knowledge.json → sources
条目id、专题、标题、摘要、状态、章节data/knowledge.json → records
引用source_ids + 章节 source_ids关联来源 id
关系目标条目与关系类型related / relationships
游戏需求ability_id、0/1/2、规则版本游戏条目的 demands
构建输出页面、索引、关系反向链接由 scripts/build.py 自动生成

编辑与发布

  • 新增或修改 JSON 条目与来源；不要直接改生成的详情页面。
  • 执行 python3 scripts/build.py，再执行 python3 scripts/validate.py。
  • Git 查看 diff，提交内容与生成页面，推送 main；GitHub Pages 自动发布。
  • 大改动先通过分支/PR 审查；来源访问范围与结论更新记录保留在变更日志。
  • 引用、关系和相对页面链接由构建/检查约束，避免扩充后产生孤立或失效页面。

后续扩充

按条目 id 拆分 JSON/Markdown、增加多作者审查字段、版本化证据提取和问题跟踪；内容规模增长后可增加全文检索或数据库 API。迁移时保留稳定标识、来源与关系语义。在线编辑和用户数据属于独立阶段，不与知识内容混合。
